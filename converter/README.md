# EPC データコンバーター

ホンダ電子パーツカタログ（EPC）の CD-ROM データをお持ちの方が、
ISO イメージを入力するだけで、EPC 部品検索アプリ用のデータ
（アプリ用 DB と画像パック）を自分の手元で生成するためのツールです。

このリポジトリにはホンダのデータそのものは含まれていません。
変換はすべて手元のマシンで完結し、生成データは各自の正規データから
作られます。

## 入力

- **DISC1 の ISO イメージ**（11CD081 / 2008-01 など）— 必須
- **DISC2 の ISO イメージ**（21CD 系）— 任意。指定すると対象カタログが増えます
  （モデルマスタには 190 カタログ分の車種が載っていますが、DISC1 に
  部品・図データがあるのは 82 カタログです。DISC2 側カタログのデータは
  DISC2 を渡した場合に変換されます）

FD インストーラは変換に**不要**です。FD に入っているのは元の
Windows プログラム本体で、部品・車種・図のデータはすべて CD 側にあります。

複数ディスクの扱い: 先に指定したディスクが優先され、後のディスクは
不足しているカタログ／ファイルだけを補います。

## 出力（--out ディレクトリ）

| パス | 内容 |
|---|---|
| `epc_v4.db` | Android アプリ用 SQLite データベース |
| `packs/<カタログ>.zip` | カタログ別 図画像パック（DISC1 のみなら 82 本） |
| `epc-*.html` | 単一 HTML ビューア（`--ipad-catalogs` 指定時のみ） |

作業データは `--work`（デフォルト `<out>/work`）に置かれます：
抽出した .CD ファイル、デコードした図 PNG（`figures/`）、
マスタ索引 DB（`index.sqlite`）、ステージ完了スタンプ（`stamps/`）。

## 使い方

```sh
# DISC1 のみ
python3 convert_epc.py --iso /path/to/HONDA_EPC.ISO --out ./out

# DISC2 もある場合
python3 convert_epc.py --iso DISC1.ISO --iso2 DISC2.ISO --out ./out

# iPad / ブラウザ用の単一 HTML も作る（カタログ指定）
python3 convert_epc.py --iso HONDA_EPC.ISO --out ./out \
    --ipad-catalogs 11SA702,11SC701
```

再実行すると、完了済みステージはスタンプによりスキップされ、
途中から再開します。やり直したい場合は `--force` を付けるか、
`--stage export,packs` のようにステージを明示してください
（明示したステージは必ず実行されます）。

### ステージ構成

| ステージ | 処理 |
|---|---|
| extract | ISO から .CD ファイルを抽出 |
| index | 車種・装備・グループ・部品・適用情報を索引 DB 化 |
| figures | 図ファイルを PNG にデコード（CCITT G4 復号）＋ホットスポット抽出 |
| figuremap | 各図面バリアントに図 PNG を対応付け |
| export | アプリ用 DB `epc_v4.db` を生成 |
| packs | カタログ別画像パック ZIP を生成 |
| ipad | 単一 HTML ビューアを生成（`--ipad-catalogs` 時のみ） |

## 前提環境

- Python 3.10 以上
- Python パッケージ: `pycdlib`, `Pillow`

```sh
pip install pycdlib Pillow
```

## 目安（DISC1 のみ、本プロジェクトの検証環境）

- 所要時間: 全ステージで約 53 分（内訳: 図デコード約 36 分、
  図対応付け約 8 分、DB 出力約 8 分、その他約 2 分）。
  これは共有 vCPU の小さな VM での実測で、通常の PC ではもっと速くなります
- 作業領域: 出力先全体で約 1.5 GB（図 PNG 約 500 MB + 索引 DB 約 320 MB
  + 抽出データ約 87 MB + 出力）
- 出力: `epc_v4.db` 約 118 MB、画像パック合計 約 496 MB

## 変換仕様

フォーマットの詳細は [../EPC_FORMAT_REPORT.md](../EPC_FORMAT_REPORT.md) を
参照してください。コンバーターには解析で確定した以下の修正が
最初から組み込まれています。

- PLMST.CD は長さチェーンが EOF に一致するまで読む正しい解析
  （旧解析は長大レコードで打ち切り、14 カタログで部品を取りこぼしていた）
- 文字コードは cp932（`shift_jis` コーデックだと半角カナが文字化けする）
- 部品の適用情報（tail）は開始位置 `7 + tail[7]` の確定文法で解析

## 検証済みの変換結果（DISC1 = 11CD081）

| 項目 | 件数 |
|---|---|
| 部品（parts） | 609,952 |
| 車種（models） | 26,651（うち DISC1 カタログ分がアプリ側に収録される） |
| 図（figures） | 15,270（デコード失敗 0） |
| ホットスポット | 473,997 |
| 図面対応（figure_map） | 15,291 / 15,291（100%） |
| 適用情報の解析成功 | 609,705 / 609,952（99.96%、残りは適用データ自体が無い部品） |

生成 DB はプロジェクトの参照 DB と全テーブル照合済みで、内容が異なるのは
1 行だけです： 部品番号 77961SD4N81（カタログ 11SD401）は品名欄が空欄で
価格だけがある記録で、参照 DB 側は旧修復スクリプトの解釈
（品名='27000'、価格なし）が残っています。コンバーターは元の解析と
同じ解釈（品名=''、価格=27000）で出力します
（同部品の 11SD411 / 11SG001 分は参照 DB 側もこの解釈です）。

## 注意

- 生成されたデータ（DB・PNG・パック・HTML）はホンダの著作物の
  派生物です。再配布はしないでください（このリポジトリの
  `.gitignore` は生成物をコミット対象から外しています）。
- DISC2 未指定でもエラーにはならず、DISC1 の範囲で正常に変換されます。
